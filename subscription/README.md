# 訂閱機制設定說明(Google 試算表 + Apps Script)

名單放在您自己的 Google 試算表裡,這個 repo 不存任何訂閱者資料。

## 運作方式

| 誰 | 做什麼 | 結果 |
|---|---|---|
| 讀者 | 在智庫的 `subscribe.html` 填姓名、單位、Email 送出 | 名單新增一列,狀態「待審」;您收到通知信 |
| 您 | 在試算表把狀態改成「核准」 | 自動寄「訂閱已開通」通知信 |
| 您 | 不同意 → 改成「退回」 | 不寄信,也不會收到電子報 |
| 您 | 直接在名單新增一列(填 Email,狀態選「核准」) | 等同手動加入,同樣會寄開通信 |
| 您 | 出刊後,選單「ISMS智庫 → 發送本期」 | 寄給所有「核准」的人;每期每人只寄一次 |
| 讀者 | 點信尾「取消訂閱」→ 在頁面按確認 | 狀態變「取消」,之後不再寄 |

## 第一次設定(約 10 分鐘)

請全程用 **isms@123hi.org** 登入 Google,信才會從這個地址寄出。

1. **建立試算表**:開 <https://sheets.new>,命名為「ISMS智庫訂閱名單」。
2. **貼上腳本**:選單「擴充功能 → Apps Script」,把編輯器裡原有的內容全部刪掉,貼上本資料夾 `Code.gs` 的全部內容,按儲存。
3. **初始化**:回到試算表重新整理頁面,上方會多一個「ISMS智庫」選單 → 點「① 初始化」。
   第一次會跳出授權畫面,選 isms@123hi.org 並允許。腳本需要的權限是:讀寫這份試算表、以您的名義寄信、連到智庫網站讀取信件內容。
4. **部署成網頁應用程式**:回到 Apps Script 編輯器,右上「部署 → 新增部署作業」:
   - 類型選「網頁應用程式」
   - 執行身分:**我**
   - 誰可以存取:**所有人**(讀者不需登入 Google 才能申請)
   - 按「部署」,複製產生的網址(`https://script.google.com/macros/s/…/exec`)
5. **把網址交給 Claude**:貼到對話裡說「這是訂閱網址」,Claude 會填進 `data/manifest.js` 的 `subscribeApi` 並開 PR。合併後智庫的訂閱頁就會開始運作。
6. **測試**:用自己的另一個信箱到訂閱頁申請 → 確認收到通知信 → 在試算表改成「核准」→ 確認收到開通信 → 選單「預覽本期」→ 點信尾「取消訂閱」確認狀態變成「取消」。

## 每月出刊時

1. 新一期合併上線後(Claude 會一併產生 `mail/latest.json`)。
2. 試算表選單「ISMS智庫 → 預覽本期(只寄給我自己)」,確認內容與連結。
3. 「ISMS智庫 → 發送本期給所有核准的訂閱者」,確認人數後送出。
4. 結果會記在「寄送紀錄」工作表。寄到一半失敗沒關係,再按一次只會補寄還沒收到的人。

## 維護名單

- **欄位**:Email、姓名、單位、狀態、來源、申請時間、核准時間、取消時間、取消碼(隱藏)、最近寄送期別、備註。
- **批次匯入既有客戶**:把 Email、姓名、單位貼進名單,再逐列把狀態選成「核准」(一次貼上整欄狀態不會觸發開通信,這時只會靜默加入)。
- **停止寄給某人**:狀態改成「取消」或「退回」。
- **刪除某人的資料**(當事人要求刪除時):直接刪除該列。
- 「取消碼」欄請不要改,那是每個人專屬的取消連結。

## 限制與注意

- **寄信額度**:Google Workspace 帳號透過腳本每日可寄的收件人數有上限(以 Google 公告為準),幾十人的名單遠低於上限。選單「名單統計」會顯示今日剩餘額度。
- **修改腳本後**要重新部署:「部署 → 管理部署作業 → 編輯 → 版本選『新版本』」,網址不會變。
- **名單就是個資**:試算表不要開共用連結;只分享給需要的人。
- 腳本內建的防護:每個 Email 短時間內重複送出會被略過、每小時受理上限、隱藏欄位擋機器人、擋試算表公式注入;申請結果一律回覆相同訊息,不會洩漏某個 Email 是否在名單內。
- 信件沒有加 `List-Unsubscribe` 標頭(Gmail 的簡易寄信功能不支援);名單大到上百人時建議改用電子報平台。
